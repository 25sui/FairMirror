# 切换到完全体模式计划

## 研究结论

当前项目有两种运行模式：

1. **简化模式**（`simple_main.py`）：
   - 内置简化的用户认证（内存存储）
   - 内置简化的JD分析（规则匹配）
   - 不依赖外部数据库和AI模型

2. **完全体模式**（`main.py`）：
   - 使用完整的API路由系统（auth, jd, resume, interview, compliance）
   - 使用SQLAlchemy数据库
   - 支持AI模型集成
   - 完整的用户权限和数据持久化

**当前问题**：
- `main.py` 中的导入检查逻辑有问题，导致总是回退到简化模式
- 我们已经修改了 `simple_main.py` 添加认证功能，但完全体模式已经有完整的认证功能
- 需要统一使用完全体模式以获得完整功能

## 计划方案

### 方案1：修复完全体模式并强制使用（推荐）

**目标**：修复完全体模式的导入问题，确保它能正常启动，并优先使用它。

**步骤**：

1. **修复 `main.py` 的导入检查逻辑**
   - 移除脆弱的 try-except 导入检查
   - 直接导入必要的模块
   - 如果导入失败，直接报错而不是回退到简化模式

2. **确保数据库初始化**
   - 添加数据库表初始化逻辑
   - 在启动时创建所有必要的表

3. **安装完整依赖**
   - 安装 requirements.txt 中的所有依赖（包括AI相关）
   - 确保 email-validator, passlib, python-jose 等已安装

4. **修改 `run.py`**
   - 简化启动逻辑
   - 优先使用完全体模式
   - 保留简化模式作为备用（可选）

5. **更新前端 API 配置**
   - 确保前端指向正确的端点
   - 验证所有API路由在完全体模式下可用

### 方案2：继续使用简化模式但完善它

如果完全体模式的依赖太复杂，可以继续使用简化模式，但需要完善它。

**步骤**：
1. 保留当前的 simple_main.py（已包含认证功能）
2. 确保所有API端点在简化模式下可用
3. 完善简化模式的其他功能

## 推荐方案

我推荐**方案1**（修复完全体模式），因为：
- 完全体模式已经有完整的架构设计
- 代码结构更清晰，可维护性更好
- 为未来扩展AI功能做好准备
- 我们已经有完整的认证API（auth.py）

## 涉及的文件

- `backend/app/main.py` - 主要需要修复的文件
- `backend/run.py` - 启动逻辑需要简化
- `backend/app/models/database.py` - 数据库初始化
- `backend/app/api/v1/auth.py` - 认证API（已存在）
- `backend/app/api/v1/jd.py` - JD分析API（已存在）
- `frontend/src/services/api.ts` - 前端API配置

## 风险考虑

1. **依赖安装问题**：torch 和 transformers 较大，可能需要较长时间
2. **数据库初始化**：需要确保SQLite数据库正确创建
3. **API兼容性**：需要确保前端调用的API在完全体模式下正常工作
